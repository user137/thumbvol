# TASKS.md

Беклог — статус, не обґрунтування (причини — в DECISIONS.md).

## v1 — зроблено

- [x] `WheelAccumulator` (core.rs) + тести (коректність/rejection/misuse), включно з фіксом
  необмеженого циклу на екстремальному вводі.
- [x] `Config` (TOML, `[wheel]`/`[general]`/`[linux]`) + `Config::save` (серіалізація назад на
  диск) + тести. `config.example.toml` у корені репозиторію.
- [x] Windows-бекенд: `WH_MOUSE_LL` хук + `SendInput` + реєстровий автостарт. **Перевірено на
  реальному MX Master** (Logitech Unifying-приймач, VID_046D) — напрямок і чутливість підтверджені
  наживо, дефолт `sensitivity` виставлено на `2` за результатом тесту.
- [x] Linux-бекенд: evdev-читання + uinput-емісія клавіш гучності + XDG autostart. **Перевірено на
  реальній Ubuntu 24.04 VM**: реальна лінковка (виявила й дала виправити реальний баг — див. нижче),
  39/39 тестів справді виконано (не лише скомпільовано), `clippy`/`fmt` чисті, автостарт-файл із
  квотованим `Exec=` записується коректно, помилка "пристрій не знайдено" виводиться акуратно й
  завершує процес чисто (без паніки/зависання). Єдине, чого досі не перевірено — end-to-end з
  реальною MX Master (на тестовій VM немає фізичної миші з `REL_HWHEEL`, лише синтетична
  Hyper-V/Azure-миша).
- [x] Windows-трей: іконка (власний глиф "бічне колесо", `assets/tray.ico`), меню Reload/About/
  Exit, підменю Sensitivity (1–5), чекбокс Invert — обидва одразу застосовуються й пишуться в
  конфіг-файл (`Config::save`), переживають рестарт. **Перевірено наживо.** Це скасовує початкове
  kickoff-рішення "без UI, лише конфіг-файл" — користувач попросив мінімальний трей у процесі
  розробки; деталі й межі — DECISIONS.md D7–D9.
- [x] CI (`.github/workflows/ci.yml`): Windows — build+test+clippy; Linux — build+test+clippy+fmt;
  окремий job — `cargo audit` (вразливості залежностей). Перший реальний прогін на GitHub Actions
  знайшов і дав виправити справжній Linux-only баг: `build.rs` гейтив `embed_resource::compile`
  рантайм-перевіркою env-змінної замість `#[cfg(windows)]` — `[target.'cfg(windows)'.build-
  dependencies]` резолвиться відносно **host**, що компілює build-скрипт, не таргету, тож з Windows
  (host=Windows) це ніколи не спливало навіть при крос-таргет `cargo check`, а на ubuntu-раннері
  (host=Linux) падало одразу. Див. CLAUDE.md.
- [x] Документація: CLAUDE.md, DECISIONS.md, README (укр. + англ.), LICENSE.
- [x] Встановлюваний пакунок: MSI (Windows, `cargo-wix`, per-user, D10) + `.deb` (Linux,
  `cargo-deb`). **Реально зібрано й перевірено, не лише скомпільовано**: MSI — локальний
  `msiexec /i` і `/x` (install/uninstall) на машині розробки, файл+реєстр-ключ ставляться й
  прибираються коректно; `.deb` — зібрано й встановлено/видалено (`sudo dpkg -i`/`-r`) на тій
  самій Ubuntu 24.04 VM, що й Linux-бекенд, `Depends: libc6` визначено автоматично
  `dpkg-shlibdeps`, autostart `.desktop`-файл реєструється з коректним `Exec=/usr/bin/thumbvol`.
  Збірка обох — окремий `.github/workflows/release.yml`, тригер на тег `v*`, не основний CI.
  Відкрита аномалія (не блокер): MSI-транзакція для "Установка й видалення програм" (ARP) не
  дала видимого запису в headless dev-сесії, хоча `PublishProduct`/`RegisterProduct` у логі —
  success; сама MSI (файли, реєстр, uninstall) працює коректно. Підтвердити на звичайній
  інтерактивній Windows-сесії при першій нагоді.
- [x] Постійне місце встановлення релізного бінарника (Windows): `%LOCALAPPDATA%\thumbvol\
  thumbvol.exe`, встановлено й запущено на машині розробки 2026-08-13. Автостарт реєструє саме цей
  шлях (перевірено — `HKCU\...\Run` містить квотований `"...\AppData\Local\thumbvol\thumbvol.exe"`),
  не `target/release`, тож перебудова/видалення build-каталогу більше не ламає автостарт. Тепер це
  ж робить і сам MSI-пакунок (D10). Ручний крок (`~/.local/bin/`) для Linux без пакунка лишається
  описаним у README як альтернатива.

## Відкрито

  лінковка/тести/автостарт уже підтверджені на тестовій VM без фізичної миші — лишається лише сам

  вже перевірена коректною, це лише питання видимості запису ARP.

## Явно поза межами v1

- Ексклюзивний grab + passthrough-пристрій на Linux, щоб глушити side-scroll так само, як на
  Windows (D1) — лише якщо це виявиться реальною проблемою на практиці.
- Ремапінг інших кнопок миші (жести, DPI-перемикання, профілі по застосунках).
- Трей-іконка/меню-налаштування на Linux (D8) — платформа не має єдиного трей-протоколу; кандидат,
  якщо GNOME/KDE-паритет виявиться потрібним на практиці.
